# 高阶挑战 3：DDR3 帧缓存 / 冻结 / 100 帧回放

## 1. 功能

| 模式 | 左半屏 | 右半屏 |
|---|---|---|
| 实时（上电默认） | 彩色原图 + 红色 Canny 边缘 + 目标框/中文标签 | Canny 二值边缘 |
| 冻结 | 实时原始彩色 | 按下 K1 那一瞬间的冻结帧（原始彩色） |
| 回放 | 实时原始彩色 | 选中的历史帧（原始彩色） |

- 冻结：镜头继续动，左屏实时更新；右屏定格在按键按下沿对应的那一帧。
  两边都显示原始彩色画面（不做边缘叠加），便于直接对比。
  再长按 K1 解除冻结。
- 回放：K2 长按从最新一帧开始，K1/K2 短按上一帧/下一帧，K2 长按退出。
- 默认上电：左彩色+红边 / 右二值边缘，目标框和标签叠加在画面上；K1/K2 短按仍然调阈值；
  K1+K2 切换 Sobel/Canny 算法模式。

## 2. DDR3 分区

每槽 4MiB（2^22 对齐），共 103 槽，约 412MB：

| 槽 | 用途 |
|---|---|
| 0 ~ 99 | 100 帧历史环，写满覆盖最早一帧 |
| 100 ~ 102 | 冻结/回放期间左屏实时画面，三缓冲轮换 |

每个槽内只有一个平面（1280×720 个 32bit 像素）：

```
[31]     帧首像素标志（只给写侧定位帧边界）
[30]     帧尾像素标志
[29:24]  0
[23:16]  中值滤波灰度 median_gray[7:0]（仍保存，当前显示不使用）
[15:0]   RGB555 + 二值边缘：{R5,G5,B5,edge}
```

显示端冻结/回放的左右两侧都取 `[15:0]` 的原始 RGB555；中值灰度仍写入
DDR（后续要做原图/中值对比时可以直接切换）。

一帧占 `1280*720*4 = 3,686,400` 字节（0x384000），槽内还剩约 508KB。

## 3. 写通路

```
摄像头 RGB565 -> 灰度 -> 中值 3x3 -> Sobel -> Canny -> 二值边缘
                    |                                      |
                    +---- rgb_align_ring 按像素序号对齐 ----+
                          RGB565 延迟 LAG=7686
                          中值灰度延迟 GRAY_LAG=6405
                                    |
                         32bit 打包 -> W0_FIFO_32 (32in/128out)
                                    |
                          AXI4 写突发 128 拍(2048B=512像素)
```

- 一帧 230,400 个 128bit 拍 = 1800 个突发，正好整除。
- Efinity 的 `W0_FIFO_32` 默认 `ENDIANESS=0`（大端）：32→128 时第一个
  写入的像素落在 128bit 字的高位 `[127:96]`。写侧的帧首标志检查 bit127，
  显示端子字取 `[127:96]/[95:64]/[63:32]/[31:0]`，与 FIFO 顺序一致；
  `tb_frame_store` 的仿真桩也按大端拼接，避免仿真/上板不一致。
- 每个突发启动前要求 FIFO 里已有完整 128 拍（`rd_datacount_o`），
  避免半空突发。
- 一帧的 1800 个 B response 全部回来后才发布该帧（`live_slot` 更新），
  读侧不会读到写了一半的帧。
- 帧首标志使写侧在帧边界切换目标槽；帧首突发的地址用**新槽基址 + 0 偏移**。

## 4. 读 / 显示通路（本版的关键改动）

旧实现用"按扫描顺序把 DDR 数据塞进显示 FIFO"的方式，DDR 读延迟一抖，
FIFO 就欠载，上板表现为黑屏/左绿右红。本版改为**按行取数 + 双 bank 行缓存**：

- 显示端每行提前一行发出取数请求，描述符包含 `{模式, 源行号, 左槽, 右槽, bank}`。
- AXI 侧在一整行时间（约 22µs）内把下一行数据取完，写入 128bit 行缓存：
  - 单 outstanding；每行按 4KB 边界切成不超过 128 拍（2048B）的突发，
    1280 宽一行 5120B 通常 3 个突发（128/128/64 或 128/64/128）。
  - 实时 3 个突发，左右对比 6 个（左右各 3）。
  - 4KB 对齐保证突发不跨页；比原来的 5×64 拍少了 2 次 AR/读延迟，
    给显示行缓存留更大余量，避免偶发横黑线（欠载）。
- 行缓存双 bank：AXI 写 bank B 的同时显示读 bank A，不会撕裂。
- 显示端从 128bit 字里取子字：
  - 实时：源像素 x -> 字 x>>2，子字 x&3。
  - 对比：640x360 每边，2x2 抽样；源像素 2m -> 字 m>>1，子字 0 或 2。
- 行缓存读地址在组最后一拍提前指向下一字，补偿 BRAM 一拍读延迟。
- 若某行取数没赶上，该行输出黑色并置 `underrun` 计数（按帧清除），
  失败模式是黑一行，而不是整屏脏数据。

带宽估算（60fps 显示）：读约 221MB/s，写约 221MB/s（摄像头 60fps 时），
合计 400 多 MB/s，远低于 DDR3 带宽。

## 5. 槽管理

- 实时：写 `ring_wr_slot`，提交后加一、到 99 回绕；`ring_count` 饱和到 100。
- 冻结/回放：写 3 个 scratch 槽轮换，历史环暂停（否则正在看的帧会被覆盖）。
- 冻结槽在按下沿锁存：长按 0.8s 确认后仍冻结 0.8s 前的那一帧；
  0.8s × 60fps ≈ 48 帧 < 100，槽不会被覆盖。
- 回放范围 `[oldest_slot, newest_slot]`，翻帧到边界钳位。

## 6. 按键

| 当前状态 | K1 短按 | K2 短按 | K1 长按 0.8s | K2 长按 0.8s | K1+K2 |
|---|---|---|---|---|---|
| 实时 | 阈值 −8 | 阈值 +8 | 冻结 | 进入回放 | 算法模式循环 |
| 冻结 | 阈值 −8 | 阈值 +8 | 解除冻结 | 进入回放 | 算法模式循环 |
| 回放 | 上一帧 | 下一帧 | 退出回放 | 退出回放 | 算法模式循环 |

- 两级同步 + 20ms 消抖。
- 短按在松开时确认；长按在按住 0.8s 时触发一次，不再附带阈值步进。
- 组合键优先：两键同时按下会取消单键长按计时。

## 9. 已知限制

- 冻结/回放模式下不叠加目标框（右图是另一帧，识别结果属于实时帧）。
- 左右对比图按 2x2 抽样成 640x360 并上下留黑边；若想看得更大，可改成
  中心裁 640x720，但会损失左右视场。
- 中值灰度仍随帧写入 DDR（[23:16]），当前冻结/回放显示的是原始彩色；
  如果以后要做原图/中值对比，把右边取 `[23:16]` 即可。
