## 三、算法原理

### 3.1 为什么用"扫描线填充率"而不是其他特征

边缘图只有轮廓、没有实心区域。对轮廓做几何判别，最廉价稳健的特征是
**轮廓在自身包围盒内的充盈程度**：

```
填充率 = 逐行"最左边缘像素 .. 最右边缘像素"游程之和 / (包围盒宽 × 高)
```

对这个量做纯数学推导：

| 形状 | 每行游程 | 填充率理论值 | ×256 |
|---|---|---|---|
| 矩形轮廓 | 恒等于整宽 W | `W·H / (W·H)` = **1.000** | 256 |
| 圆形轮廓 | 弦长 `2√(r²−dy²)` | `πr² / (2r)²` = **π/4 ≈ 0.785** | 201 |
| 三角形轮廓 | `2·(dy/H)·(W/2)` 线性增长 | `(½·W·H) / (W·H)` = **0.500** | 128 |

三者之间的间隔是 **矩形 256 → 圆 201 → 三角 128**，
相邻类别相差至少 55/256 ≈ 21%，抗噪余量很充足；
而随机噪点因为轮廓不连续、包围盒被少数离群点撑大，填充率会掉到 **~24**，
天然被排除。

### 3.2 实测标定结果

用与 RTL 完全等价的参考模型（含整数除法截断）在 640×480 上扫描，
覆盖半径 55/90、边长 120/200、线宽 1/2/3 共 15 种组合 + 1 个噪声对照组：

```
case                         edge       area   boxWxH  ratio_q  verdict
--------------------------------------------------------------------------
circle r=90 t=1              1140      25985 181 x 181      203  CIRCLE
circle r=55 t=1               696       9841 111 x 111      204  CIRCLE
rect 200x140 t=1              680      28341 201 x 141      256  RECT
rect 120x120 t=1              480      14641 121 x 121      256  RECT
tri 200x150 t=1               701      15353 203 x 151      128  TRI
circle r=90 t=2              2256      26565 185 x 185      198  CIRCLE
circle r=55 t=2              1392      10189 115 x 115      197  CIRCLE
rect 200x140 t=2             1352      28341 201 x 141      256  RECT
rect 120x120 t=2              952      14641 121 x 121      256  RECT
tri 200x150 t=2              1493      15655 205 x 151      129  TRI
circle r=90 t=3              3388      27145 187 x 187      198  CIRCLE
circle r=55 t=3              2072      10557 117 x 117      197  CIRCLE
rect 200x140 t=3             2016      28341 201 x 141      256  RECT
rect 120x120 t=3             1416      14641 121 x 121      256  RECT
tri 200x150 t=3              2276      15957 207 x 151      130  TRI
noise (no shape)              296       9646 320 x 318       24  NONE
```

**结论**：线宽从 1 变到 3（边缘像素数变化近 3 倍）时，
填充率只波动 ±6，类别判定完全不受影响 —— 这正是选填充率而不是选
"周长/面积比"这类对线宽敏感的特征的原因。

据此定阈值（见 `shape_recognizer.v` 参数）：

```
RECT_Q = 230   (0.898)   —— 实测矩形 256，余量 26
CIRC_Q = 168   (0.656)   —— 实测圆 194~204，上余量 26 / 下余量 26
TRI_Q  =  96   (0.375)   —— 实测三角 128~134，上余量 32 / 下余量 72
MIN_EDGE = 200           —— 噪点对照组仅 296，正常形状 680~3388
```

### 3.3 RTL 实现要点

**（1）单遍扫描，流水线无阻塞**

每来一个边缘像素，同时更新：

- `acc_edge` 计数（≈周长）
- `row_first / row_last` 记录本行最左/最右边缘列号
- 行结束时（`x_cur == H_ACTIVE-1`）把 `row_last - row_first + 1` 累加到 `acc_fill`
- `acc_minx/maxx/miny/maxy` 维护包围盒

全部是加减法和比较，没有乘法器、没有除法器进入像素路径，
每个像素 1 个时钟，不丢像素、不产生背压。

**（2）除法只做一次**

填充率需要一次除法，但**每帧只在帧末做一次**。
用 32 位顺序式恢复余数除法器（`dv_st` 状态机，32 拍完成），
资源代价约 40 个 LUT + 1 个 32 位减法器，相对于
921600 像素/帧的吞吐完全可以忽略。

```
ratio_num = acc_fill << 8          // 分子预先放大 256 倍
ratio_q   = ratio_num / box_area   // 结果即"填充率 ×256"，0~256
```

**（3）帧末时序对齐 —— 本设计最容易踩的坑**

累加器在 `fe_d`（`frame_end` 打一拍）那一拍才全部定型，
所以：

- 除法器在 `dv_st==0` 且 `fe_d` 时采样 `box_area` / `ratio_num`；
- 结果锁存器（`feat_edge` / `box_*`）也在 `fe_d` 时采样累加器；
- 累加器本身在 `fe_d` 时清零，为下一帧做准备。

**注意**：`acc_any` 在 `fe_d` 被清零，如果分类时直接判断 `!acc_any`
会永远得到"未识别"。因此额外用 `any_r` 在 `fe_d` 锁存一份，
分类用 `any_r`。

### 4.2 为什么在显示域叠加，而不是写进 DDR

叠加层刻意放在 **DDR 读回之后、lcd_driver 之外**：

- DDR 帧缓存的数据宽度（16 bit RGB565）完全不用改；
- 叠加只依赖 `lcd_de` / `lcd_xpos` / `lcd_ypos` / 灰度值，不需要额外的行缓存；
- 像素通路全程单时钟域，**不需要对像素流做任何 CDC**，
  只有"每帧一个"的识别结果需要过 CDC。

## 五、关键设计点详解

### 5.1 视频流协议（最需要注意的一点）

本工程的 Avalon-ST 视频流是**非标准**的：
`cmos_fifo2st.v` 中

```verilog
source_sop_r <= (pix_cnt == 0) && fifo_rd;
source_eop_r <= (pix_cnt >= TOTAL_PIXELS-1) && fifo_rd;
```

即 **`sop` / `eop` 标记的是"一帧"的首尾，不是"一行"的首尾**。
因此 `shape_recognizer` 里不能靠 sop 判行，必须用

> **只在 `valid` 时自增的行/列计数器**（`x_r` / `y_r`，每 `H_ACTIVE` 个像素绕回）

来推导当前像素坐标。这样即使 `valid` 因为采集 FIFO 供数不上而断续，
坐标依然正确 —— 这一点在测试平台的"valid 有停顿"用例里专门做了验证。

### 5.2 跨时钟域传递

识别结果产生在 `w_cmos_pclk`（约 74.25 MHz），显示在 `clk_pixel`（74.25 MHz），
两者同频但**相位无关**，不能直接打拍传递。

采用**电平翻转握手**（`shape_result_cdc.v`）：

1. 源端先把 `shape / box / ratio` 锁存进 `*_s` 寄存器，**数据稳定后再**翻转 `tog_s`；
2. 目的端对 `tog_s` 做两级同步（`tog_meta` → `tog_sync`），再用
   `tog_sync ^ tog_sync_d` 检出跳变；
3. 跳变沿到来时把源端数据锁存进 `*_b`。

**为什么这样是安全的**：结果每帧只更新一次，新数据到来前旧数据已经稳定保持了一整帧
（921600 个时钟），远大于两级同步器需要的建立/保持时间 + 传输时延，
所以目的端采样到的数据一定是稳定的那一份，不存在亚稳态采到"半新半旧"的风险。

### 5.3 中文提示的实现

`font_cn_rom.v` 由 `tools/genfont.ps1` 用 GDI+ 渲染 SimSun 16px
（`SingleBitPerPixelGridFit` 消除抗锯齿）生成，共 13 个字：

```
索引  字形   索引  字形   索引  字形   索引  字形
 0    检      4    形      8    别     12    标
 1    测      5    矩      9    三
 2    到      6    未     10    角
 3    圆      7    识     11    目
```

复合出四句提示语：

| shape | 提示语 | 配色 |
|---|---|---|
| 0 未识别 | 未识别 | 红 `FF4040` |
| 1 圆形 | 检测到圆形 | 青 `00FFFF` |
| 2 矩形 | 检测到矩形 | 绿 `00FF00` |
| 3 三角形 | 检测到三角形 | 黄 `FFFF00` |

**字模寻址不含除法**：文字放大倍数 `S` 限定为 2 的幂（1/2/4），
于是"第几个字 / 字内第几列 / 字内第几行"全部用**移位 + 掩码**得到：

```verilog
localparam GSZ = 16 * S;
localparam SLG = (S == 1) ? 0 : ((S == 2) ? 1 : 2);   // log2(S)

wire [3:0] gidx = txr >> (4 + SLG);          // 第几个字
wire [3:0] gcol = (txr >> SLG) & 4'hF;       // 字内列
wire [3:0] grow = (tyr >> SLG) & 4'hF;       // 字内行
wire font_pix   = font_bits[15 - gcol];      // 行字 MSB 在最左
```

默认 `S=2`，即每字 32×32 像素 —— 1280×720 画面上清晰可读。

`font_preview.png` 是字模的直接渲染预览，可先用它确认文字效果。

### 5.4 叠加层的绘制优先级

```
文字 > 文字底板 > 包围盒边框 > 原灰度图
```

底板颜色 `24'h101018`（接近黑），保证任何画面背景下文字都清晰；
包围盒边框宽 `BOX_THICK=2` 像素，颜色与提示语同色，一眼能对应上。

坐标对齐：`lcd_driver` 的 `H_AHEAD = 12'd1` 使 `lcd_xpos` 比图像列号大 1，
所以叠加层里 `px = xpos - X_SHIFT`（`X_SHIFT=1`）把两者对齐。

## 八、现场调试与参数整定

### 8.1 识别不出来 / 误识别

按这个顺序排查：

**① 先看屏幕上有没有包围盒**
- 包围盒总是红色 + "未识别" → 边缘不够，**把 `EDGE_THRESH` 调小**（24 → 16）
  或换更高对比度的目标物/更强补光；
- 完全没有框 → 查看 `valid_b`（可用 `w_shape_valid_disp` 引到 LED 观察），
  没置位说明识别模块没收到帧，检查 `sobel_valid/sop/eop` 连线。

**② 框是斜的 / 明显偏大**
说明背景里有边缘被算进去了 —— **缩小 ROI**。
默认 ROI 是画面正中 480×360 窗口（`ROI_X0/X1/Y0/Y1 = 400/879/180/539`），
把目标物放在这个窗口内：

```verilog
.ROI_X0(480), .ROI_X1(799)     // 更窄的 320x360 窗口
.ROI_Y0(180), .ROI_Y1(539)
```

**③ 圆形被认成矩形**
圆形填充率 201、矩形 256，阈值 230 在中间。
若圆形画得太小（半径 < 20 像素），轮廓离散化会让填充率虚高 ——
**用较大的目标物**（屏幕上半径 ≥ 50 像素），或把 `CIRC_Q` 提到 180。

**④ 三角形被认成圆形**
三角形 128 vs 圆 201，间隔很大，一般不会错。若发生，说明三角形底边没被完整检测到
（底边是水平边缘，Sobel 对水平边缘的响应通常比斜边强，但若底边出画就会只剩两条边
变成一个"尖角"形状）—— 保证三角形完整落在 ROI 内。

### 8.2 阈值速查

| 参数 | 默认 | 作用 | 调整方向 |
|---|---|---|---|
| `thresh` / `EDGE_THRESH` | 24 | 边缘二值化阈值 | 小→更敏感（噪点多），大→更干净（可能丢轮廓） |
| `MIN_EDGE` | 400（实机） | 最小边缘像素数 | 目标物小时调小 |
| `RECT_Q` | 230 | 矩形判定下限 | — |
| `CIRC_Q` | 168 | 圆形判定下限 | 小圆被认成矩形时调大 |
| `TRI_Q` | 96 | 三角形判定下限 | 噪点多误判成三角时调大 |
| `roi_en` | 1 | ROI 使能 | 置 0 = 统计全画面 |
| `S` | 2 | 文字放大倍数（须为 2 的幂） | 觉得字小可改 4（每字 64×64） |
| `BOX_THICK` | 2 | 包围盒线宽 | — |

## 九、演示建议

1. **准备素材**：白纸上打印/手绘黑色粗线条的圆形、矩形（长方形）、三角形轮廓，
   线条宽度 ≥ 3 mm，尺寸占画面 1/3 左右。用纯色背景（白墙/白纸）。
2. **降低边缘阈值**：室内光线下把 `EDGE_THRESH` 调到 16 效果更好。
3. **演示顺序**：先展示无目标时的画面（红框 + "未识别"），
   再依次放上圆形 → 矩形 → 三角形，屏幕上文字和框的颜色会实时切换。
4. **可加一句对比**：切换 `roi_en` 为 0，展示 ROI 对背景干扰的抑制作用。

## 十、已知限制

- 一次只识别**一个**目标（整帧 ROI 内所有边缘统一算一组特征）。
  多目标需要做连通域标记，属于另一个量级的改动。
- 只能区分**凸的、轴对称性强的**基本形状；心形/星形等会被判为"未识别"。
- 判据是形状的**充盈程度**，所以一个"画得特别圆的六边形"会被认成圆形 ——
  这是特征匹配法的固有性质，演示时使用标准形状即可。
- 视频流的 `sop/eop` 假设每帧恰好 `H_ACTIVE × V_ACTIVE` 个有效像素。
  若更换摄像头分辨率，必须同步修改 `H_ACTIVE/V_ACTIVE` 与
  `Sobeledge_8d_proc` 的 `WIDTH/HEIGHT` 参数。
